# API Test Runner & Report Output Contract

## Output Contract (CI/CD-stable — DO NOT change without bumping schemaVersion)

The interfaces below are pinned. Downstream CI/CD pipelines, GitHub Actions workflows, and the cross-app dashboard depend on them. Any change requires coordinated updates across this prompt + `/tdgs-aidlc-setup-testdata` + `/tdgs-aidlc-generate-api-tests` + every consuming GitHub Action. The reference implementations in Sections 5–5b below MUST satisfy this contract — if implementation and contract drift, the contract wins and the implementation is a defect.

| Contract | Pinned value |
|---|---|
| npm scripts | `test`, `test:full`, `test:test`, `test:stage`, `test:report`, `test:inso`, `test:verbose`, `test:dry-run`, `test:collection` |
| Output files | `test-results/results.json`, `test-results/results.previous.json`, `test-results/data-ledger.json`, `test-results/test-summary.html`, `test-results/test-report.md` |
| `data-ledger.json` `schemaVersion` | `"api-v2"` |
| `results.json` REQUIRED top-level fields (R10-C3) | `service` (string), `environment` (string), `runId` (string `"run-{ISO}"`), `timestamp` (ISO-8601 — alias for `startTime`), `startTime` (ISO-8601 — when the runner began), `endTime` (ISO-8601 — when the runner finished and the file was atomically written), `durationMs` (integer milliseconds = `endTime - startTime`; MUST equal `summary.durationMs`), `baseUrl` (string), `executor` (`"inso"\|"node-fallback"`), `tests` (array), `summary` (object). The dashboard's run-time-window chart and stale-run detection ("is this report fresher than the previous?") REQUIRE `startTime`+`endTime`; without them the cross-app dashboard cannot compute per-service throughput or detect stuck runs. `timestamp` is retained for back-compat with v1 readers but new code MUST consume `startTime`/`endTime`. |
| `results.json` per-test REQUIRED fields (R10-C4 amended) | `name`, `endpoint`, `category`, `status`, `durationMs` (integer milliseconds), `request` (`{method,url,headers,body}` resolved), `response` (`{status,headers,body}` 4 KB-truncated), `assertions` (array), `error` (nullable string). OPTIONAL: `dataWarning`, `skipReason` (G9b structured), `placeholderHits[]`, `unresolved[]`, `dataIssueReason`, `dataSources[]`. The `dataSources[]` array (R10-C4) is OPTIONAL but MANDATORY when ANY `{{catalog.*}}` token was substituted in this test — each entry is `{ field: "<dot.path>", source: "catalog.identityPool.<poolType>\|catalog.stubs.<stubName>\|catalog.captured\|faker\|literal\|inline-placeholder", resolvedValue: "<post-resolution literal, plain text — no masking or redaction>" }`. The Section 6 (Endpoint → Catalog Tokens Used) of the per-service report and the workspace dashboard's Test Data section BOTH read this array; without it, both renderers vacuous-pass with empty cells. |
| Status enum (closed) | `pass`, `fail`, `skip`, `data-issue`, `infra`, `generation-bug`, `unresolved-token` |
| Summary counter mapping | `summary` has exactly 5 status counters: `passed`, `failed`, `skipped`, `dataIssue`, `infra`. The two pre-send-guard statuses roll up into `dataIssue` for the math invariant: `generation-bug` → `dataIssue`, `unresolved-token` → `dataIssue`. The original status string is preserved on each `tests[]` entry so the dashboard's "Generation Bugs" section can filter on it. OPTIONAL non-invariant fields: `skippedCrossService` (integer — tests skipped because they target a different service in multi-collection runs), `durationMs` (integer — wall-clock time for the suite), `passRate` (integer 0–100, percentage — computed as `Math.round((passed / executed) * 100)`). These are informational and excluded from the math invariant. |
| Canonical summary read-key (R10-C3a — DOWNSTREAM CONTRACT) | The aggregated KPI block on `results.json` is named **`summary`** and ONLY `summary`. Every downstream reader (`generate-report.js`, `generate-workspace-dashboard.js`, `run-tests` Step 9d) MUST read `results.json.summary` first — no fallback chain to `testSummary`/`counters`/`stats`/`totals`. Runner MUST NOT emit aliases. Pre-publish self-check in `/tdgs-aidlc-setup-testdata` Step 4a greps the dashboard script for literal `r.data.summary` and aborts if absent. The `data-ledger.json` companion field is named `testSummary` (intentionally distinct) — feeds catalog write-back only, never KPI tiles. |
| Math invariant | `passed + failed + skipped + dataIssue + infra == total` AND `executed <= total` (asserted by both runner and report-generator). Note: `skipped` tests (e.g. env-blocked) are NOT counted in `executed` but ARE counted in `total` — so the invariant checks against `total`, not `executed`. |
| Exit codes | `0` = all tests passed; `1` = one or more tests in a non-pass status (test failure, data-issue, infra, generation-bug, unresolved-token); `2` = harness error (cannot read collection, cannot write `results.json`, math invariant violated). CI MUST distinguish `1` (tests ran, some failed) from `2` (harness itself broke). |
| Auto-invoke report generator | After writing `results.json` + `data-ledger.json` and persisting catalog status, the test-runner MUST auto-invoke `generate-report.js` via `child_process.execFileSync(process.execPath, [path.join(__dirname, 'generate-report.js')], { stdio: 'inherit' })`. Wrap in try/catch (non-fatal). Without this, reports go stale. |
| Shared dashboard update contract (R10-C5 — CROSS-APP) | `generate-report.js` MUST append to the workspace dashboard (`{docs-repo}/test-data/dashboard.html`) and `db-transactions.json` after writing per-service reports. Rules: **(a) Tiles are CUMULATIVE** — read existing Total/Passed/Failed values via value-regex (`/<div class="value(?:\s\w+)?">(\d+)<\/div><div class="label">X/`), ADD this run's counts, write back. NEVER replace the entire tiles section. **(b) Run History uses 10 columns** matching the table headers: Run, Service, Type (badge), Timestamp, Total, Pass, Fail, Rate, Duration, Test Data Used. **(c) Run number** is derived by scanning existing `<td>#(\d+)</td>` and incrementing max (same logic as functional globalTeardown). **(d) Atomic write** — `.tmp` → `rename` per Hard Rule #15. **(e) DB Records** — append before `</table>` after `<!-- Section 3: DB Records Created -->`. **(f) db-transactions.json** — read existing, push to `runs[]`, atomic write. Both API and functional runners share this dashboard — any writer that REPLACES instead of accumulating corrupts cross-suite history. |
| `generate-report.js` Section 7 (Data Ledger) self-explanatory rendering — MANDATORY | Section 7 MUST emit two annotated sub-sections (NOT bare tables): **(7a) Captured Values** — JSONPath extractions injected as `{{captured.<name>}}` into downstream consumers; rows whose value matches `/^<UNCAPTURED:/` render red (`background:#fdecea;color:#a93226`) with tooltip explaining producer failed or JSONPath mismatch + downstream `chain-broken` skip; header surfaces UNCAPTURED count when > 0 (e.g. `(15 total — 3 UNCAPTURED ⚠️)`). **(7b) DB Records Created** — server-generated identifiers from write responses; header splits total into `created` / `echo-only` (amber `#b9770e`, key === `(response-echo-only)`) / `failed` (grey `#7f8c8d`, key === `(none)` or outcome !== `created`); table includes 5th column `HTTP` showing `responseStatus`. |
| Catalog token grammar | Two namespaces are supported: `{{catalog.identityPool.<poolType>.<fieldName>}}` for identity-pool fields and `{{catalog.stubs.<stubName>.<fieldName>}}` for stub/fixture data. Any `{{catalog.*}}` token outside these two namespaces is an unresolved-token failure. |
| Test-code injection signature (CI/CD-stable — TEST AUTHORING CONTRACT) | Each `unit_test.code` runs inside `new AsyncFunction('insomnia', 'expect', 'Ajv', 'addFormats', ut.code)`. `insomnia.send()` resolves to `{status, data, headers, elapsedTime}` where `elapsedTime` is integer ms since request start — satisfies `/tdgs-aidlc-generate-api-tests` unit-test-code-patterns.md rule #5 SLA assertion (`expect(resp.elapsedTime).to.be.below(2000)`). `insomnia.addFormats` is exposed as a property — satisfies `/tdgs-aidlc-generate-api-tests` post-generation-checks.md Check 17 (`insomnia.addFormats(new Ajv({allErrors:true,strict:false}))`). `Ajv` and `addFormats` ALSO injected as positional args for back-compat. Adding/removing any of these surfaces requires bumping `schemaVersion` AND coordinated update to generate-api-tests skill. |
| Captured token grammar | Only `{{captured.<key>}}` where `<key>` matches a `capture` entry on a prior request resource. |
| Pre-send guards (always-on) | (a) `<UNCAPTURED:…>` sentinel sweep, (b) literal-placeholder guard (Positive/SETUP only), (c) unresolved-`{{…}}` sweep — applied in that order before HTTP send. |
| Environment gating (`requiresEnv`) | A `unit_test` resource MAY declare `"requiresEnv": ["test", "stage", "prod"]` to indicate which environments the test can meaningfully execute in. When the current `--env` does not appear in that array, the runner skips the test with `status: 'skip'` and `error: 'env-blocked: requires [<list>] but running in <current>'`. Use this for tests that depend on external services, payment gateways, or DB state that only exists in certain environments. The optional `"requiresEnvReason"` field (string) documents WHY the gate exists for human analysis of skip reports. |
