# Verification, Documentation, and Phase-4 Augmentations

## Step 8 — Establish Selector and Stability Conventions

- Prefer `data-testid` or accessible-role selectors (`getByRole`, `getByLabel`, `getByText`)
- **NEVER assume HTML element IDs** — always read the actual component source to find the real `id`, `name`, or `data-testid`. If a React component renders `<input id="streetAddress1">`, use `#streetAddress1` — not a guessed alias like `#address1`.
- **For react-select fields**, do NOT use `#fieldName` (it points to a hidden input inside the react-select container). Instead, use the helper from Step 7a that navigates the react-select div structure.
- **For date picker fields with masked inputs**, do NOT use `.fill()`. Use the helper from Step 7b that uses `.pressSequentially()` for character-by-character entry.
- **Anchor tags styled as buttons** — Scan for `<a>` elements with button-like CSS classes (`btn`, `button-primary`, `button-secondary`, `btn-primary`, `btn-link`, etc.) or visually styled as buttons. These are common for back/cancel/home navigation actions. In page objects, use `getByRole('link')`, `locator('a.{className}')`, or `getByText('{label}')` for these — NOT `getByRole('button')`. Document the actual element type (button vs link) next to each page object action method.
- **Language/locale toggle** — Read the actual component source to determine how the toggle works. It may be a `<button>`, a framework `<Link>` component with `onClick` (no `href`), or a native `<a>` tag. Do NOT assume it has an `href` pointing to `/{locale}/`. Many apps switch language via click handlers that call `i18n.changeLanguage()` or `router.navigate()` programmatically. Use the correct selector based on the actual rendered element.
- Document wait/timeout strategy in README
- Handle conditional UI gracefully (check element existence before interaction)

## Phase-4 Augmentations — Parity & Reliability

Referenced by `generate-functional-tests` and `run-tests`. Close gaps vs. legacy tool.

### A4-1 — Failure-artifact verification (post-run sanity check)

Playwright HTML report MUST display screenshot+video+trace per FAILED test. After every run, the runner/report-generator MUST:

1. Read `test-results/results.json`.
2. For each test with `status ∈ {failed, timedOut}`: assert one attachment each named `screenshot`, `video`, `trace` with file present at `attachment.path`.
3. Assert `test-results/html-report/index.html` references those basenames.
4. On failure: emit `⚠️ failure artifacts not linked in report` warning with testIds; **continue** — do NOT mask the test failure.

### A4-2 — Real-mode notification verification helper (mandated when notification flows exist)

When the catalog declares an `external-required` recipient pool with email-shaped fields, scaffold `support/helpers/notification-verifier.js` exporting `verifyNotificationDelivered({ recipient, subjectMatch, timeoutMs })`:

- `mock` mode → returns `{ delivered: true, source: 'mock', body: '<canned>' }` immediately.
- `real` mode → polls provider test-inbox API. Provider URL+creds MUST come from `project-context.md` `notificationProviderConfig:` (do NOT hard-code provider names). If absent, ASK user to choose: `mailosaur` | `yopmail` | `mailtrap` | `local-smtp` | `none` (degrades to `{ delivered: null, source: 'no-provider' }` with warning).
- `delivered: false` → test marks `failed` reason `notification-not-delivered`.
- `delivered: null` → test marks `skipped` reason `notification-verification-unavailable`.

Parity replacement for legacy tool's manual "check the inbox" step.

### A4-3 — Accessibility audit opt-in

Scaffold `support/helpers/a11y-audit.js` exporting `runA11yAudit(page, { tags = ['wcag2a','wcag2aa'], skipFailures = true })` using `@axe-core/playwright` (add to devDependencies). Specs opt in per flow via descriptor `"a11y": { "enabled": true, "failOnViolations": false }`.

### A4-4 — File-upload/download patterns

Scaffold:
- `support/fixtures/sample.pdf` (10 KB), `sample.png` (5 KB), `sample.csv` (1 KB) — fixed-content fixtures.
- `support/helpers/file-helpers.js` exporting `uploadFile(page, selector, fixtureName)` (uses `page.setInputFiles()`) and `downloadFile(page, action, expectedExt)` (uses `page.waitForEvent('download')`).

Descriptor schema supports `step.kind = 'upload-file'` (`step.fixture`, `step.selector`) and `step.kind = 'download-file'` (`step.action`, `step.expectedExtension`).

### A4-5 — Negative-case coverage is structural, not optional

Every generated spec MUST include positive AND at-least-one-of-each `negative-validation`/`boundary`/`negative-business-rule` per testable form (subject to `generate-functional-tests` priority tiers). Positive-only spec = defect; `caseType` enum (G11) enforces distribution.
